# mcp-docx: adversarial audit and user-value run

Date 2026-09-03. Scope: `servers/docx` only. Zero paid API calls. Zero network calls: the server makes
none (`grep -rE "fetch\(|https?://|node:http|node:net|node:dns" src/` returns nothing outside the
checkout URL string), and the run itself called no external service.

## Method

**Part 1 harness** — `/private/tmp/docxaudit/probe.mjs` spawns `dist/index.js`, writes JSON-RPC lines to
stdin and flags any stdout line that does not parse as JSON. Fresh `XDG_DATA_HOME` per lane
(`/private/tmp/docxaudit/data`, `data2`, `cdata`), `MCP_LICENSE_KEY=""` so every probe runs on the free
tier. Fixtures are generated by `/private/tmp/docxaudit/fixtures.mjs`.

**Strict reader for every generated .docx** — `npx -y @anthropic-ai/mcpb` is an unrelated package
(MCP bundles) and was not used. Each package is instead checked three ways:

1. `unzip -t <file>` — the ZIP container and every CRC.
2. A well-formedness pass over `word/document.xml`: a tag scanner that keeps an element stack, requires
   every close tag to match its open tag, requires an empty stack at the end, and rejects a raw `<` in
   character data. `@xmldom/xmldom` and `fast-xml-parser` are not in `node_modules` and were not added,
   so this is the balance check, not a validating parser. It is asserted in
   `test/adversarial.test.mjs::assertWellFormed`, so it runs on every `npm test`.
3. LibreOffice headless PDF conversion — **skipped, `/Applications/LibreOffice.app` is not present on
   this machine**. No PDF render proof exists in this round.

Result: 7 packages from Part 1 and 4 from Part 2, all `unzip:OK XML:OK`.

**Part 2 harness** — the real `claude` CLI as an MCP client against `/private/tmp/uv30/mcp.json`, which
registers `docx` alone (`--strict-mcp-config`), with fresh `XDG_DATA_HOME=/private/tmp/uv30/data` and
`XDG_CONFIG_HOME=/private/tmp/uv30/cfg`, `MCP_LICENSE_KEY=""` (free tier). One session, `--session-id`
then `--resume`, so scenario 3 can say "that file". Per-tool allowlist written out by name (10 entries);
`--allowedTools "mcp__*"` grants nothing, as rounds 4-6 already measured.

### The two that mattered

**Silent overwrite (12/14).** `doc_create`, `doc_from_markdown`, `doc_to_html`, `doc_fill_template`,
`proposal_create` and `contract_create` all ended in a bare `writeFileSync(path, buf)`. Writing a second
proposal to a path a client document already occupied destroyed it with no warning and no way to tell
from the answer. Fix: `outputPath()` refuses an existing target unless the new `overwrite: boolean`
argument is `true`, and the refusal names the flag. The check runs **before** `mkdirSync`, before the
document is built for the disk, and inside the same lock that allocates the reference number.

**`record()` turning a written file into an error (24).** `writeDoc()` wrote the .docx and then appended
to the history. A corrupt `documents.json` made `addDoc()` throw, the tool returned
`Error: ... nothing was written.` and the user had a real .docx on disk they had been told did not exist.
Fix: `record()` is best-effort and returns the reason as text; every tool appends it to its own success
answer. The store's own quarantine behaviour is unchanged and still correct.

Also fixed on the way: `forEachParagraph()` **stopped** the whole scan the first time `indexOf("<w:p")`
landed on something that only starts like a paragraph (`<w:pgSz`, `<w:permStart`, `<w:proofErr`).
Everything after that point was silently left unfilled. It now skips the false hit and keeps scanning;
`blocksOf()` had the same shape and got the same fix.
