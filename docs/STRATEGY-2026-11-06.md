## 2. THE FOUR THINGS THAT ARE ACTUALLY TRUE

**1. The payment rail works. Demand does not exist.**
This is the correction to the obvious hypothesis. I assumed the buy button was fake
and probed it; the probe returned `x-mcp-buy: scripted-ua-no-session` because it was a
curl request. Driving the real buyer path (browser UA, same-origin `Origin`,
`Sec-Fetch-Mode: navigate`, `intent=checkout`) produced a genuine live-mode Stripe
session. The worker holds a live key; `/success` and the webhook fulfillment paths are
implemented. Nothing about the plumbing is broken.

What is broken is upstream: 334 buy clicks produced 100 checkout confirmations and zero
payments, and 2,780 open/expired sessions in one week carried no PaymentIntent. Those
were automation crossing the guard, i.e. our own probes, not buyers. Organic traffic to
the store is effectively zero (0 of 299 URLs indexed), so there is no population from
which a conversion rate could even be computed. **Conversion optimisation at this
traffic level is arithmetic on zero.** Distribution is the only lever with leverage.

**2. Twelve percent of the catalog was a 404, and that is now fixed.**
Twelve catalog entries returned 404 on `/mcp/<name>` because the worker never imported
them — an omission, not a broken deploy. Eleven are now vendored under `remote/src/vendor/`
and wired into the `SERVERS` map; all eleven serve tools in production (39 tools
recovered). Deployed as version `330e03ce`, commit `47f5185e`, suite 112/112.

**3. The asset is the factory, not the inventory.**
58 servers and 588 tools produced $0 in months. The evidence for why is in the market
itself: 66.3% of 4,811 tracked MCP servers have zero uses, no registry has a billing
rail, and developers do not pay for software they can run free. A $39 lifetime key on a
free-runnable package is priced below its value and shaped against recurring revenue.
What has demonstrable value is the capability to ship a production MCP server with
auth-gated tools, a hosted endpoint and tests in days. That sells to businesses that own
an API and no MCP server, at $1,500–3,000 per build — one or two engagements beat any
conceivable per-seat revenue from this catalog.

**4. Registry placement is the only organic channel with compounding returns.**
Google is not going to deliver this traffic in any useful timeframe (0 indexed, and the
`/buy` path is disallowed). But registry pages *are* indexed and *do* rank for
"<thing> mcp server". A listing is a permanent inbound link plus a discovery surface
inside Cursor, Claude, VS Code and Smithery, at zero marginal cost, and it does not
depend on our own domain ever ranking. The target list writes itself: `price-tracker`
and `time-tracker` are measured-empty categories, so a well-formed listing can be the
first answer on the surfaces that matter.
